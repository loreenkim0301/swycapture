# 의사결정 기록 (decisions)

이 폴더는 **논의가 끝난 것만** 온다. 진행 중인 논의(버그 리포트, 디자인 시안, 확인이 필요한 지점)는
GitHub Issue/PR에서 타임라인 그대로 오간다 — 그게 원본이다. 여기 오는 문서는 그 논의가 끝난 뒤,
"결론만 빠르게 읽을 수 있는 색인"이다. 대화 전체를 옮겨적지 않는다.

## 왜 이렇게 나누나
- 사람은 과정을 시간순으로(이슈/PR 타임라인) 보는 게 편하다
- Claude(에이전트)는 세션마다 저장소 안 파일을 자동으로 읽으므로, 다음 세션에서 "왜 이렇게
  했더라"를 다시 묻지 않으려면 결론이 저장소 안에 있어야 한다
- 그래서: **진행 중 = Issue/PR, 종료 후 = 여기**

## 언제 만드나
Issue가 닫히거나 PR이 머지돼서 결정이 확정되면 만든다. 사소하고 자명한 변경(오타 수정 등)까지 전부
만들 필요는 없다 — 버그 원인 규명, 디자인 방향 결정, 여러 대안 중 하나를 고른 경우처럼 "왜"가
나중에 궁금해질 만한 것만.

## 파일명
`NNNN-짧은-제목.md` — 4자리 순번, 소문자-하이픈. 예: `0001-sidebar-default-open.md`

## 규칙
- 한 번 쓴 파일은 고치지 않는다. 이후 결정이 이전 걸 뒤집으면 새 번호로 파일을 만들고, 그 안에
  "supersedes 0001"이라고 적는다
- [TEMPLATE.md](TEMPLATE.md)를 복사해서 시작한다
